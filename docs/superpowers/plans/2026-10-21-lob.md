# LOB (location-based scheduling) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LOB in the clone (core, MCP, desktop): a P6-native LOB project kept in the same XER as its CPM projects, built on the clone's CPM.

**Architecture:** An `LobModel` (locations, tasks, segments, quantities, crews, drivers, logic, takt) is the source of structure. `expandLob` turns it into ordinary activities, relationships, codes and UDFs through `applyOps` (journalled, undoable), F9 schedules everything, and `pace` applies continuity as start-on-or-after constraints. The model travels in the XER as a project notebook (base64 JSON + SHA-256) plus a project UDF flag, and in a `.lob.json` sidecar.

**Tech Stack:** TypeScript (Node 24.14.0 type stripping: erasable TS, `.ts` imports), React desktop, the existing MCP server.

**Spec:** `docs/superpowers/specs/2026-10-21-lob-design.md`

## Global Constraints

- Up to 6 location levels; activity IDs `<task code>-<location code>`, stable across insert/reorder of locations.
- Duration of a location = work ÷ (crews × crew size × productivity × hours per day) × production factor; work = Σ quantity × consumption.
- Driver matrix exactly as the spec's table (crew / rate / duration; refused edits use the spec's wording); every edit returns `changes: [{task, segment?, location?, field, old, new}]`.
- Timing options: `asap`, `paced`, `asap_paced` (default).
- Logic layers 1–5 and buffers (days or locations) as the spec states; cross-project links in any direction.
- Storage: project UDF `Schedule Method` = `LOB (P6 clone)`; notebook topic `LOB model (P6 clone)` (split `n/m` above 32 KB), base64 JSON with SHA-256; `<file>.lob.json` always beside an XER holding an LOB project; activity codes `Location` (hierarchical) and `Trade`; activity UDFs `LOB Quantity`, `LOB Consumption`, `LOB Crew`.
- Expanded activities: duration, logic, location and trade read-only outside the LOB tools (message: "set by the LOB plan: edit it in Extensions > LOB (or lob_edit)").
- MCP tools prefixed `lob_`; existing tools work on LOB projects unchanged.
- Agreement with real P6: early start/finish of every activity and the project finish, for the XER as exported.

## Review Focus

1. A task with a zero quantity in some locations: those locations have no activity, and logic passes through them.
2. Inserting a location in the middle of the tree after progress exists: existing IDs, progress and baselines unchanged.
3. A paced task whose successor link would pull it apart (circular continuity): continuity yields, never loops; the answer says which task could not be paced.
4. A notebook altered in real P6 (HTML-wrapped, truncated): detected by the hash, rebuilt from codes/UDFs or the sidecar, and said so.
5. Crew rounding under the `duration` driver: the reachable total is reported, never silently different from the asked one.

### Task 1: The model and the driver matrix

**Files:** Create `core/lob/model.ts`, `core/lob/durations.ts`; Test `tests/lob-model.test.ts`

**Interfaces — Produces:**
- `interface LobLocation { code: string; name: string; level: number; parent: string | null; factor?: number }`
- `interface LobQuantity { location: string; quantity: number }`, `interface LobItem { name: string; unit: string; consumption: number; quantities: LobQuantity[] }`
- `interface LobSegment { from: string; to: string; crews: number; crewSize: number; productivity: number; driver: 'crew' | 'rate' | 'duration'; rate?: number; duration?: number; timing: 'asap' | 'paced' | 'asap_paced'; factors?: Record<string, number> }`
- `interface LobTask { code: string; name: string; trade: string; precision: number; order: string[]; items: LobItem[]; segments: LobSegment[]; hoursPerDay?: number; calendar?: string }`
- `interface LobLink { kind: 'task' | 'location'; pred: string; succ: string; type: 'FS' | 'SS' | 'FF' | 'SF'; lagDays: number; precision?: number; locationLag?: number; bufferDays?: number; bufferLocations?: number; predLocation?: string; succLocation?: string; project?: string }`
- `interface LobModel { version: 1; project: string; levels: string[]; locations: LobLocation[]; tasks: LobTask[]; links: LobLink[]; takt?: LobTakt }`
- `locationDurations(m: LobModel, t: LobTask): Map<string, number>` (days, per location in the task's order; zero work → absent)
- `edit(m: LobModel, op: LobEdit): { model: LobModel; changes: LobChange[] }` (pure; refusals throw `LobRefused`)

- [ ] Test the matrix: for each row of the spec's table (edited crew / rate / segment duration / quantity / location duration / factor) × driver (crew / rate / duration), assert the changed fields and that nothing else moved; assert the refusal message "the rate is held; change the driver or the rate"; assert `duration` driver reports `asked`/`got` after crew rounding; zero quantity removes the location.
- [ ] Implement; run `node --test tests/lob-model.test.ts`; commit.
